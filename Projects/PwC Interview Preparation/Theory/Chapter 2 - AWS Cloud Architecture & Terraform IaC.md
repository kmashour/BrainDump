## 🕸️ 1. AWS VPC Secure Networking Topology

In a Senior DevOps interview, you must design network security boundaries demonstrating a clear separation between public-facing and private compute zones.

### A. Subnet Segmentation
*   **Public Subnets:** Associated with a Route Table that has a default route (`0.0.0.0/0`) pointing directly to an **Internet Gateway (IGW)**. Public IPs are assigned to hosts here. Only public endpoints (load balancers, NAT gateways, bastion hosts) live in this subnet.
*   **Private Subnets:** Associated with a Route Table directing default outbound traffic (`0.0.0.0/0`) to a **NAT Gateway** located in a public subnet. Hosts here receive only private IPs, ensuring they are shielded from direct inbound internet traffic.

### B. Internet Access Control
*   **Internet Gateway (IGW):** A horizontally scaled, redundant, and highly available VPC component that enables communication between resources in your VPC and the internet. Performs 1-to-1 NAT translation.
*   **NAT Gateway:** Performs source NAT translation (many-to-1), allowing instances in private subnets to request packages/patches outbound while blocking external internet hosts from initiating inbound sessions.
*   **NAT Gateway HA Sizing:** A NAT Gateway is constrained to a single Availability Zone. For production multi-AZ architectures, deploy one NAT Gateway per availability zone. If a zone fails, the corresponding private subnet traffic remains operational.

### C. Security Groups vs. Network Access Control Lists (NACLs)
Explain the stateless/stateful boundary at the networking layer:

| Property | Security Groups | Network ACLs (NACLs) |
| :--- | :--- | :--- |
| **Operational Layer** | Instance Network Interface (ENI) | Subnet Boundary |
| **State Nature** | **Stateful:** Inbound allowed traffic automatically permits return outbound traffic regardless of rules. | **Stateless:** Outbound return traffic must be explicitly permitted via rules. |
| **Evaluation Order** | All rules are evaluated concurrently; permits only (no deny rules). | Evaluated sequentially by rule number (supports explicit allow and deny rules). |
| **The Ephemeral Port Trap** | Unrelated to return traffic ports. | Outbound rules must explicitly allow access to **ephemeral ports** (`1024-65535`) to allow return traffic packets. |

## 🔑 2. AWS IAM Security Model & Trust Federation

Secure access management is the foundation of Cloud Compliance (SOC 2, GDPR).

### A. Users vs. Roles vs. Instance Profiles
*   **IAM User:** Associated with long-lived credentials (password, access keys). High exposure risk if developers hardcode them.
*   **IAM Role:** Associated with temporary credentials (valid for 15 minutes to 12 hours) dynamically generated by the AWS Security Token Service (STS). Assigned to trusted services (e.g. EC2, Lambda) or federated users.
*   **Instance Profile:** A container for an IAM Role that passes permissions to an EC2 instance. The `kubelet` or local instance application queries the EC2 Metadata Service (IMDSv2) at `http://169.254.169.254/latest/meta-data/iam/security-credentials/` to obtain active temporary security tokens.

### B. OIDC Identity Federation (EKS / GitHub Actions)
Instead of creating IAM Users with static keys for external systems (like GitHub Actions workflows), establish an **OIDC Trust Provider**.
*   **Mechanism:** GitHub acts as an OpenID Connect identity provider. You configure an IAM Identity Provider in AWS trusting GitHub's OIDC certificate.
*   **Trust Policy:** The IAM Role trust policy specifies that only the GitHub OIDC provider is allowed to assume the role, restricted to your specific repository path:
    `"token.actions.githubusercontent.com:sub": "repo:kmashour/BrainDump:ref:refs/heads/main"`
*   **Result:** GitHub Actions obtains short-lived STS tokens dynamically, eliminating key rotation administrative burdens.

## 🛠️ 3. Infrastructure as Code (IaC) with Terraform

Articulate state management mechanics and declarative lifecycle operations.

### A. Remote State & DynamoDB Locking
*   **The State File (`terraform.tfstate`):** A JSON document mapping resource declarations to physical cloud resource IDs. Contains sensitive credentials (database passwords, API keys) in plain text.
*   **Remote Storage Backend:** State must be stored securely in S3 with server-side encryption enabled.
*   **DynamoDB State Locking:** Multiple runs against the same state file corrupt the configuration. Terraform locks the S3 state file by writing a lock record into a DynamoDB table containing a primary key `LockID`. Subsequent runners will fail initialization until the active run releases the lock.

### B. Advanced Resource Lifecycle Constraints
To write resilient code, utilize resource lifecycle blocks:
*   **`prevent_destroy = true`:** Prevents Terraform from accidentally destroying critical resources (databases, main VPCs) during an apply run.
*   **`create_before_destroy = true`:** Modifies Terraform's default replacement behavior (which destroys the resource *first*, then creates the replacement). Used to prevent application downtime (e.g. provisioning a new launch template instance before terminating the old one).
*   **`ignore_changes = [tags]`:** Instructs Terraform to ignore modifications to specific attributes (such as tags applied dynamically by security scanning agents on AWS), preventing state drift loops.
