## 🏛️ Linux Network Stack & Firewall Architectures

Linux processes network packets through the kernel's network stack, which is tightly integrated with the **Netfilter** packet-filtering framework.

### The Netfilter Framework & Hooks
Netfilter hooks allow modules (like iptables or nftables) to inspect, alter, or drop packets at five key execution phases inside the kernel network traversal path:

```
                  [Packet In]
                       |
                       v
                 +------------+
                 | PREROUTING | ---> (DNAT, Route Decision)
                 +------------+
                       |
        +--------------+--------------+
        |                             |
        v                             v
  (Local Host?)                 (Routed Host?)
        |                             |
        v                             v
  +-----------+                 +------------+
  |   INPUT   |                 |  FORWARD   |
  +-----------+                 +------------+
        |                             |
        v                             |
  [Local Process]                     |
        |                             |
        v                             |
  +-----------+                       |
  |  OUTPUT   |                       |
  +-----------+                       |
        |                             |
        +--------------+--------------+
                       |
                       v
                +-------------+
                | POSTROUTING | ---> (SNAT / Masquerade)
                +-------------+
                       |
                       v
                  [Packet Out]
```

1.  **PREROUTING:** Catches packets before a routing decision is made. Used for Destination Network Address Translation (DNAT).
2.  **INPUT:** Processes packets destined for local host user-space sockets.
3.  **FORWARD:** Processes packets passing through the host to another destination (requires `/proc/sys/net/ipv4/ip_forward` to be enabled).
4.  **OUTPUT:** Processes packets generated by local host processes before they exit.
5.  **POSTROUTING:** Catches packets after routing decisions are completed. Used for Source Network Address Translation (SNAT / Masquerading).

### iptables vs. nftables (Modern replacement)
*   **`iptables`:** Configured via discrete tables (`filter`, `nat`, `mangle`) and linear chain rules. Rule execution evaluates each line sequentially, leading to high CPU latency on massive rule lists.
*   **`nftables`:** Modern replacement. Uses a unified address-family framework (`inet` for IPv4/IPv6) and processes rules using a kernel-internal bytecode virtual machine. It uses search trees and dictionary lookups, dramatically accelerating packet routing times.

**Comparative Configurations:**
```bash
# ----- Legacy iptables syntax -----
# Allow incoming SSH from a specific CIDR block
iptables -A INPUT -p tcp --dport 22 -s 10.0.0.0/8 -j ACCEPT

# Configure NAT Masquerading on outgoing interface
iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE

# ----- Modern nftables syntax -----
# Create unified filter table and chain
nft add table inet my_filter
nft add chain inet my_filter input_rules { type filter hook input priority 0 \; }

# Add rule allowing SSH and HTTP
nft add rule inet my_filter input_rules tcp dport { 22, 80 } accept
```

## 🌐 Software-Defined Networking (SDN) & Open vSwitch

Traditional networking couples control (routing logic) and data (packet switching) planes on individual switches. Software-Defined Networking (SDN) separates these planes to enable centralized software control.

### Planes of Operation
*   **Control Plane:** The centralized logic (SDN Controller) that decides packet paths and programs the switching rules.
*   **Data Plane (Forwarding Plane):** Simple switches/nodes that forward packets according to flow-table rules programmed by the control plane.
*   **Management Plane:** Configures and monitors device states.

### Linux Bridge vs. Open vSwitch (OVS)
*   **Linux Bridge:** The legacy kernel driver that simulates a simple hardware bridge, widely used in standard VM and container setups.
*   **Open vSwitch (OVS):** An enterprise-grade virtual switch designed for multi-tenant virtualization. It supports flow-table program execution via the OpenFlow protocol and handles tunnels (VXLAN, GRE) dynamically.

```bash
# Configure standard Linux Bridge
brctl addbr br0
brctl addif br0 eth0

# Configure Open vSwitch (OVS)
ovs-vsctl add-br ovs-br0
ovs-vsctl add-port ovs-br0 eth0

# Add OpenFlow rule: forward traffic from port 1 out of port 2
ovs-ofctl add-flow ovs-br0 "in_port=1,actions=output:2"
```

## 🔌 Network Function Virtualization (NFV)

Network Function Virtualization (NFV) replaces physical hardware appliances (firewalls, routers, load balancers) with software equivalents running as Virtual Machines or Containers (known as **Virtual Network Functions - VNFs**).

### Core Components
*   **VNFs (Virtual Network Functions):** The software appliances (e.g. pfSense as a virtual firewall, HAProxy as a load balancer).
*   **NFVI (NFV Infrastructure):** The physical and virtualized resources (servers, hypervisors, storage, virtual networks) that run the VNFs.
*   **MANO (Management & Orchestration):** The software framework that manages the provisioning, lifecycle, and chaining of VNFs.

### Service Function Chaining (SFC)
SFC steers network packets through an ordered sequence of virtual network functions before sending them to the final destination.
*   *Example Chain:* incoming packet -> Decryption VNF -> Firewall VNF -> DPI (Deep Packet Inspection) VNF -> Target Application.

## 🎛️ Enterprise Routing Protocols (OSPF & BGP)

For large-scale routing, dynamic protocols calculate the best paths across complex topologies automatically.

### OSPF (Open Shortest Path First)
*   **Type:** Link-state routing protocol.
*   **Scope:** Interior Gateway Protocol (IGP) used within a single administrative domain (Autonomous System).
*   **Mechanism:** Every router builds a complete topological map of the network (Link-State Database) and uses Dijkstra's Shortest Path First algorithm to construct its routing table. It divides the network into hierarchical **Areas** (with Area 0 acting as the core Backbone Area) to minimize routing update broadcast storms.

### BGP (Border Gateway Protocol)
*   **Type:** Path-vector routing protocol.
*   **Scope:** Exterior Gateway Protocol (EGP) that connects different Autonomous Systems (AS) across the global Internet.
*   **Mechanism:** BGP exchanges path attributes (vectors of AS numbers) between peer BGP speakers.
*   **Peering Types:**
    *   **External BGP (eBGP):** Exchanging routes between routers in different Autonomous Systems.
    *   **Internal BGP (iBGP):** Exchanging external routes inside the same Autonomous System.
